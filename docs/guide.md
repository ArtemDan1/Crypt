# Crypt — подробности

## Секреты

Раздел «Секреты» хранит логины, SSH-ключи, токены, карты и защищённые заметки.
Скрытые значения раскрываются по кнопке на 30 секунд. Копирование выполняет Rust;
буфер очищается через 15/30/60/90 секунд (по умолчанию 30), если после этого вы
не скопировали что-то другое. Значения помечаются ConcealedType для менеджеров буфера.

При смене значения предыдущее доступно в «Истории». **Удаление секрета необратимо**:
вместе с записью удаляется история, в корзину секрет не попадает.
Генератор использует системную случайность, длину 8–128 и выбранные классы символов.
Для TOTP можно вставить base32 или `otpauth://totp/…`; приложение показывает код,
сам ключ TOTP не раскрывается. Пароли и значения не сохраняются в Pinia/localStorage.
В браузерном dev-моке значения живут только до перезагрузки страницы, SSH/TOTP там демонстрационные.

## Бэкап и импорт

В Настройки → Хранилище можно сохранить всю базу в `.cryptbackup` после подтверждения Touch ID или PIN.
Бэкап открывается исходной сид-фразой и восстанавливается при первом запуске через «Из бэкапа»; PIN и Touch ID настраиваются заново.
Экран «Импорт» принимает CSV Chrome/Safari/Firefox/Edge/Brave, QR Google Authenticator, JSON Aegis (включая зашифрованный) и открытый экспорт 2FAS.
Там же доступны KeePass, Markdown/Obsidian и SSH; перед импортом создаётся снимок, а после CSV/QR можно отправить исходные файлы в системную Корзину.

## ssh-agent

1. Создайте ed25519-ключ или импортируйте приватные OpenSSH/PEM-ключи из `~/.ssh`
   на экране «Импорт». Зашифрованный ключ расшифровывается при импорте,
   пароль импорта не сохраняется. Исходные файлы приложение не изменяет.
2. В карточке включите «Доступен ssh-agent», а в настройках — «ssh-agent».
3. Нажмите «Добавить в ~/.ssh/config». Блок `IdentityAgent` добавится в конец,
   перед первой записью создастся `config.crypt-backup`; кнопка «Убрать» удалит только блок Crypt.
   Ваши более ранние настройки `IdentityAgent` сохраняют приоритет.

Вместо изменения config можно задать переменную для текущего терминала:

```bash
export SSH_AUTH_SOCK="$HOME/Library/Application Support/dev.crypt.app/agent.sock"
ssh-add -l
```

Каждая подпись подтверждается Touch ID или паролем Mac. Опция «Доверять ключу после
подтверждения» действует на конкретный ключ 1/5/15 минут; по умолчанию подтверждение
нужно каждый раз. Блокировка сбрасывает доверие. Параллельные подписи показывают диалоги по очереди.

Для подписи при заблокированном хранилище включите вход по Touch ID: публичные ключи
берутся из кэша Keychain, а после подтверждения агент временно открывает хранилище
только для подписи. Окно остаётся заблокированным. Если быстрый вход не настроен или
подтверждение отменено, подпись отклоняется, Crypt показывает экран входа.

Закрытие окна прячет приложение в меню-бар; агент продолжает работать. «Открыть Crypt»
возвращает окно, второй запуск фокусирует первый экземпляр. ⌘Q / «Выйти Crypt» завершают
приложение. Автозапуск при входе настраивается там же и запускает Crypt без окна.

## Где лежат данные

- Хранилище: `~/Library/Application Support/dev.crypt.app/vault/`. Зашифровано всё, кроме `vault.json` и `device.json`.
- Настройки: `~/Library/Application Support/dev.crypt.app/settings.json` (без секретов).
- Ключ для быстрого входа и обёртка PIN: связка ключей входа, сервис `dev.crypt.app`.

## Подпись без платного Apple Developer аккаунта

Ключ данных хранится в связке ключей входа, и macOS разрешает доступ к нему только приложению с той же подписью.
Ad-hoc-подпись меняется при каждой сборке, поэтому после каждой пересборки macOS спрашивает
«разрешить доступ к связке ключей?». Чтобы подпись не менялась:

1. Откройте «Связка ключей» → «Ассистент сертификации» → «Создать сертификат…».
2. Имя: `Crypt Local Signing`, тип идентификации: «Самоподписанный корневой», тип сертификата: «Подписание кода».
3. В `apps/desktop/src-tauri/tauri.conf.json` добавьте
   `"bundle": { "macOS": { "signingIdentity": "Crypt Local Signing" } }`.
4. Выполните `cd apps/desktop && pnpm tauri build`. Приложение появится в `target/release/bundle/macos/Crypt.app`.

`pnpm tauri dev` запускает неподписанный бинарник, поэтому запросы связки ключей в режиме разработки — это нормально.

Touch ID работает через LocalAuthentication, отдельные права (entitlements) ему не нужны.
Если Touch ID недоступен (нет сенсора, закрыта крышка), macOS спросит пароль Mac.

Известная слабость этой схемы: отпечаток проверяет приложение, а не сама связка ключей.
Она защищает от кражи диска, от бэкапов и от человека за клавиатурой, но хуже защищает от вредоноса,
который уже запущен под вашим пользователем. С платным аккаунтом можно перейти на data-protection keychain
с биометрическим ACL (см. `src-tauri/src/unlock/`).
