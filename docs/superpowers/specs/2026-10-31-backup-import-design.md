# Crypt: бэкап и импорт

Дата: 2026-10-31
Статус: на согласование
Макеты: https://claude.ai/artifact/PCSwUujPE9RMxKYTJeKVua — `Settings.dc.html` (раздел «Хранилище»), `Restore.dc.html`, `Import.dc.html`, `Onboarding.dc.html` (третий вариант).
Связан с редизайном: `2026-10-31-redesign-seal-design.md` (тема, компоненты, анимации берутся оттуда).

## Зачем

1. Сейчас хранилище живёт только на одном Mac. Нужен способ сохранить всю базу в один зашифрованный файл и восстановить её на новом Mac при первом запуске.
2. Перенос паролей и кодов 2FA из браузеров и аутентификаторов должен быть быстрым, иначе Crypt не заменит то, чем владелец пользуется сейчас.

## Цели

- Ручной экспорт всей базы в файл `.cryptbackup`, который открывается **той же сид‑фразой**, которой создано хранилище (решение владельца).
- Восстановление из такого файла **только при первом запуске** (онбординг).
- Импорт паролей из CSV‑выгрузок Chrome, Safari, Firefox, Edge, Brave.
- Импорт кодов 2FA: Google Authenticator (QR‑коды экспорта), Aegis (JSON, в т.ч. зашифрованный), 2FAS (JSON).
- Единый экран «Импорт», куда переезжают и существующие KeePass, Markdown и SSH‑ключи из `~/.ssh`.

## Не цели

- Автоматические бэкапы по расписанию (решение владельца: пока вручную).
- Восстановление поверх существующего хранилища или слияние двух хранилищ.
- Чтение баз браузеров напрямую (зашифрованы ключом из Связки ключей; хрупко и выглядит как вредонос). Только CSV, который пользователь выгрузил сам.
- Экспорт из Crypt в CSV/другие менеджеры.
- Импорт из Authy и Microsoft Authenticator (у них нет экспорта).
- Отдельный пароль для бэкапа.

## Анти‑цели

- Бэкап, который можно открыть без сид‑фразы, или в котором что‑либо лежит открытым текстом (кроме служебного заголовка без пользовательских данных).
- PIN, обёртки ключа и прочее из Связки ключей в бэкапе (иначе файл даёт перебирать PIN офлайн — см. основной дизайн).
- Импорт, который молча теряет данные: всё пропущенное или не распознанное перечисляется в отчёте.
- Открытые пароли из CSV/JSON/скриншотов, остающиеся в памяти или временных файлах дольше импорта.

## Бэкап

### Формат
Хранилище на диске — папка (`vault.json`, `device.json`, `keycheck.bin`, `seed.bin`, `meta.bin`, `objects/*.bin`), содержимое уже зашифровано ключом из сид‑фразы. Бэкап — эта папка, упакованная в один файл:
- небольшой открытый заголовок: магия `CRYPTBAK`, версия формата, дата создания, число объектов (без названий и любых пользовательских данных);
- архив файлов хранилища как есть.
Конкретный контейнер (tar, zip без сжатия, свой формат) — решение исполнителя. Повторно шифровать архив не обязательно: файлы внутри уже зашифрованы, а `keycheck.bin` позволяет проверить фразу.

### Экспорт (Настройки → Хранилище, карточка «Бэкап всей базы»)
1. «Экспорт бэкапа…» → подтверждение Touch ID / PIN (как для показа сид‑фразы).
2. Системный диалог сохранения, имя по умолчанию `Crypt-ГГГГ-ММ-ДД.cryptbackup`.
3. Упаковка с прогрессом; хранилище в это время не меняется (взять блокировку или упаковать согласованную копию).
4. Итог: имя, размер, «Показать в Finder».
- Под карточкой: «Последний бэкап: <дата>». Дата хранится локально (не в бэкапе). Если бэкапа нет или он старше 30 дней — мягкое напоминание в этой строке (решение исполнителя‑дизайнера: 30 дней, без всплывающих окон).
- Что входит: всё содержимое папки хранилища — записи, секреты, типы, папки, история версий, снимки, корзина. Что не входит: Связка ключей (PIN, Touch ID), настройки приложения.

### Восстановление (онбординг → «Из бэкапа», макет `Restore.dc.html`)
1. Выбор файла `.cryptbackup` (диалог или перетаскивание). Проверка заголовка и версии; понятные ошибки «Это не файл бэкапа Crypt» / «Файл от более новой версии Crypt».
2. Ввод сид‑фразы (24 слова, счётчик). Проверка фразы по `keycheck.bin` **до** распаковки в рабочую папку. Неверная фраза — тряска и «Эта фраза не подходит к файлу бэкапа».
3. Распаковка во временную папку рядом с местом хранилища, проверка открытием (`open_with_seed`), затем атомарное перемещение на место.
4. Дальше — шаг «Быстрый вход» из обычного онбординга (Touch ID, PIN).
- Доступно только когда хранилища нет (`noVault`).
- Идентичность устройства: восстановленное хранилище на новом Mac должно получить **новый** идентификатор устройства, чтобы правки двух машин не путались в истории/CRDT (решение исполнителя‑дизайнера; исполнитель проверяет, как `device.json` используется, и делает так, чтобы старое и новое устройство не совпадали).

## Импорт

Единый экран «Импорт» (макет `Import.dc.html`), вход из Настройки → Хранилище и кнопкой «Импорт» в шапке «Секретов». Шаги: источник → инструкция и выбор файла → предпросмотр → импорт → итог. Существующий `TransferSection.vue` (KeePass, Markdown) и `SshImportDialog` переезжают сюда с прежней логикой.

### Общие правила
- Всё разбирается локально; файлы читаются в память, временных копий нет.
- Предпросмотр до записи: сколько будет создано, сколько дублей пропущено, сколько не распознано, первые строки (пароли замаскированы).
- Папка назначения по умолчанию: «Импорт из браузера · ДД мес», «Импорт 2FA · ДД мес» и т.п.; можно выбрать другую.
- Импорт — одна операция (как KeePass: снимок перед импортом, чтобы его можно было откатить, если существующий механизм это делает).
- Итоговый отчёт перечисляет пропущенное и причины.

### Браузеры (CSV)
- Инструкция по выгрузке для выбранного браузера (тексты — в макете).
- Формат определяется по заголовкам CSV; поддержать колонки Chrome/Edge/Brave (`name,url,username,password,note`), Safari (`Title,URL,Username,Password,Notes,OTPAuth`), Firefox (`url,username,password,httpRealm,formActionOrigin,guid,timeCreated,timeLastUsed,timePasswordChanged`). Неизвестные заголовки — понятная ошибка со списком ожидаемых.
- Каждая строка → секрет «Логин»: название (из `name`/`Title`, иначе домен), `username`, `password`, `url`, заметка; `OTPAuth` из Safari → `totp_seed` через существующий `parse_totp`.
- Дубли: точное совпадение (домен + логин + пароль) с уже существующим логином или другой строкой файла — пропуск. Тот же домен и логин, но другой пароль — импортируется отдельной записью (решение владельца в обсуждении).
- Строки без пароля — пропуск с отметкой в отчёте.
- После импорта — предупреждение «файл хранит пароли открытым текстом» и кнопка «Переместить в корзину» (системная Корзина macOS, не корзина Crypt).

### Google Authenticator (QR)
- Инструкция: на телефоне «Перенести аккаунты → Экспортировать», скриншоты QR на Mac.
- Источник изображений: вставка из буфера (⌘V) и выбор файлов (несколько сразу). Захват области экрана — не в этом объёме.
- Распознавание QR и разбор `otpauth-migration://offline?data=…` (protobuf `MigrationPayload`: secret, name, issuer, algorithm, digits, type). Поддержать пакеты из нескольких QR (batch index/size) и обычные `otpauth://totp/` QR. HOTP — пропуск с отметкой в отчёте.
- После импорта — подсказка удалить скриншоты (кнопка отправляет выбранные файлы в системную Корзину; для вставки из буфера — только текст подсказки).

### Aegis и 2FAS (JSON)
- Aegis: открытый и зашифрованный экспорт (для зашифрованного — запрос пароля; формат Aegis vault: scrypt + AES‑GCM, по документации Aegis).
- 2FAS: открытый экспорт `.2fas`. Зашифрованный 2FAS — понятное сообщение «экспортируйте без пароля» (решение исполнителя‑дизайнера; поддержку можно добавить позже).

### Куда кладутся коды 2FA
- Для каждого кода ищется существующий секрет‑логин по совпадению сервиса: домен из `url` логина ↔ `issuer` (без регистра, с учётом поддоменов) и, если есть, `username` ↔ имя аккаунта.
- Найден ровно один и у него нет `totp_seed` → код добавляется к нему.
- Иначе → новый секрет «Логин» с названием `issuer`, логином = имя аккаунта и `totp_seed`.
- В предпросмотре для каждой строки видно «к логину X» или «новый секрет»; правило сопоставления — решение исполнителя‑дизайнера, переключатель «не сопоставлять, всё новыми» — по желанию исполнителя.

## Ограничения

- Разбор форматов и упаковка — в `crates/crypt-core` (рядом с `vault/import_keepass.rs`), с тестами на образцах файлов каждого формата; команды Tauri — в `commands/transfer.rs`.
- Новые зависимости только для распознавания QR и protobuf, если без них никак (маленькие, без сети).
- Фейковый бэкенд `pnpm dev` получает заглушки для новых команд, чтобы экраны можно было пройти в браузере.
- Визуальная часть — по редизайну «Печать».

## Оставлено исполнителю

- Контейнер бэкапа и его заголовок (в рамках правил выше).
- Библиотеки для QR и protobuf (или ручной разбор protobuf — формат маленький).
- Как именно не держать открытые значения дольше нужного (зануление буферов и т.п.).
- Порядок: разумно бэкап → браузеры → Google Authenticator → Aegis/2FAS → перенос KeePass/Markdown/SSH на общий экран.
